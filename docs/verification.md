# 05 验证与评估方案

> 目标：**证明 vdot 指令正确（功能）且值得（性能/能效）**。功能验证以"三方一致 + difftest 兜底"为核心，评估以"可复现、口径明确"为原则。指令语义以 [02_指令集设计](./02_指令集设计.md) 为准。

---

## 1. 验证目标与层次

| 层次 | 对象 | 方法 | 通过标准 |
| --- | --- | --- | --- |
| L0 指令语义 | 软件仿真器 / NEMU / Spike | 指令级测试 + 随机差分 | 三方一致，100% 用例通过 |
| L1 硬件功能 | vdot RTL（解码+执行单元） | 定向测试 + 随机 + difftest | difftest 0 失配 |
| L2 系统集成 | 昆明湖 V2 全核 | riscv-tests + 向量测试 + 内核回归 | 无回归 |
| L3 性能/能效 | vdot 单元 / GEMM / LLM | 基准（口径见 §5） | 达到 01 §3.3 指标 |

## 2. 指令级测试矩阵

以 [02 §6 行为表] 为基础扩展：

| 类别 | 用例（示例） | 覆盖点 |
| --- | --- | --- |
| 基本 | 4 种符号性 × 2 形式 × 手工算例 | 语义正确性（含负数、符号扩展） |
| vl 边界 | vl=0、vl=1..VLMAX-1、vl=VLMAX、vl>VLMAX | 元素计数、尾元素 |
| 掩码 | 全 1/全 0/交替/随机、掩码寄存器 EEW 对齐 | 掩码粒度=32 位元素 |
| vstart | vstart=0（正常）、vstart≠0 → **illegal instruction**（与昆明湖所有向量算术指令一致，见 02 §4.4） | vstart 策略、非法路径 |
| 尾策略 | vta=0/1、尾元素旧值保持 | undisturbed/agnostic |
| 溢出 | 全 127、全 -128、混合极值、多轮累加 | 16 位中间无溢出、32 位回绕 |
| 非法 | SEW∈{8,16,64}、VS=Off、未定义编码 | illegal instruction（C1–C4） |
| 寄存器组 | LMUL=1/2/4/8、寄存器组越界（vs2+LMUL>31） | 寄存器组寻址与非法检测 |
| 数据布局 | 打包子元素边界（[8j,8j+7]）、大小端 | 与 §4.1 数据视图一致 |
| vx 形式 | rs1 各 4 字节组合、符号性 | 标量广播语义 |
| 随机 | 随机 vl/vstart/掩码/数据/符号性 | 与 golden 差分 |

## 3. 随机差分测试（三方一致）

```
随机激励生成器（数据/vl/vstart/掩码/符号性/LMUL）
        │
        ├──► 软件仿真器（§2.3，参考实现 1）
        ├──► NEMU/Spike（参考实现 2）
        └──► RTL 仿真（参考实现 3，emu 或 VCS）
        │
        ▼
    结果比对（vd 全寄存器 + 异常标志），失配即报错并最小化复现用例
```

- **覆盖维度**：SEW×LMUL×vl×vstart×掩码×符号性×数据模式（全极值/随机/模式化）。
- **数量**：随机用例 ≥ 1 万条指令级用例；配合 `--seed` 可复现。
- **产出**：失配用例自动生成最小复现（delta-debug），进入定向回归集。

## 4. difftest 协同仿真

- **框架**：香山 difftest（`emu --diff riscv64-nemu-interpreter-so`，流程见 [香山课程-环境篇](../../xiangshan-course/docs/1-xiangshan-development-environment/1.CHN/Chapter_8_The_Difftest_Co_Simulation_Framework.md)）。
- **前提**：NEMU 已实现 8 条指令（04 §2.1），否则 difftest 在 vdot 处必然失配。
- **测试负载**：
  1. riscv-tests 全量（回归基线）；
  2. 自研向量指令测试集（§2 矩阵编译为镜像）；
  3. 随机差分镜像（每轮 seed 不同）；
  4. kernel 冒烟（GEMM 正确性：与 fp32 参考比对误差界）；
  5. LLM 推理冒烟（per-token 输出与量化参考实现比对）。
- **通过标准**：全部 difftest 0 失配、0 死锁（forward progress）。

> ✅ **2026-08-18 vdot 差分已通过（L1 部分）**：固定用例 4/4（vdot_test / vdot_single_test / vdot_oldvd_src / vdot_src_test）+ 随机用例 24/24（随机 INT8 vs1/vs2 + INT32 oldVd）全部 GOOD TRAP，RTL 与 NEMU 一致（08 §3.3）。剩余：riscv-tests 向量全量回归（L2）、随机用例扩展至 ≥1 万（L1 完整）。

## 5. 性能与能效基准（口径定义）

### 5.1 基准分级

| 基准 | 度量 | 对比对象 | 口径 |
| --- | --- | --- | --- |
| B0 micro | vdot 吞吐（条/周期）、时延（周期） | RVV vadd/vwmacc 基线 | RTL 仿真计数 / emu 周期 |
| B1 GEMM | 每输出元素指令数、周期数、寄存器压力 | RVV 1.0 vwmacc 组合实现 | emu 周期（相同分块/打包前提） |
| B2 端到端 | per-token 延迟（ms/token）、吞吐（token/s） | 同模型 FP16/INT8 基线 | emu 或实机（如实机不可得则 emu + 估算） |
| B3 能效 | TOPS/W（INT8 点积） | vwmacc 组合路径 | 综合后功耗估算（见 §6） |

**✅ 2026-08-19 B0 emu 实测（RTL 真实周期，mcycle 计数，扣 boot=8,331 周期，N=1000 条）：**

| 指标 | vdot | vadd 基线（e32） | 说明 |
| --- | --- | --- | --- |
| 独立流吞吐（4 路 ILP） | **1.78 cyc/条**（0.56/cyc） | 1.31 cyc/条（0.76/cyc） | vdot 单条完成 4×4 点积+累加；vadd 仅 4 元素相加 → vdot 等效计算密度远高 |
| 依赖链时延 | **7.02 cyc/条** | 6.03 cyc/条 | vdot 2 级流水+乘加树，比 vadd 仅多 ~1 周期 |

> 注：vadd 基线为 e32 单元素加（对照同宽度目的寄存器）；RVV vwmacc 组合基线对比待做。B0 镜像与结果：`b0_{vdot_indep,vdot_dep,vadd_indep,vadd_dep}.bin`，emu `--no-diff` 全 GOOD TRAP。

### 5.2 B1 GEMM 指令数理论对比（设计预估）

以 VLEN=128、LMUL=1、K=4（一个输出元素的一次 4 元素点积）为粒度：

| 实现 | 每 4×4 乘加所需指令（近似） | 说明 |
| --- | --- | --- |
| RVV 1.0 组合（vzext→vwmaccu→加宽→vnsrl） | ~8–12 条 | 含拆包/符号扩展/位宽升级/打包 |
| 本设计 vdota4 | 1 条 | 一次 4 组点积+累加 |

> 注：上表为设计预估；打包成本（离线 vs 运行时）单独报告。

**✅ 2026-08-18 emu 实测（RTL 真实周期，M=N=K=16，vdot GEMM vs 标量 C GEMM）：**

| 指标 | vdot GEMM | 标量 C GEMM | 提升 |
| --- | --- | --- | --- |
| 差分正确性 | ✅ GOOD TRAP | ✅ GOOD TRAP | — |
| 指令数 | 6,797 | 86,554 | **12.7× 更少** |
| 总周期 | 10,858 | 29,361 | — |
| GEMM 净周期（扣 ~8,300 boot） | ~2,558 | ~21,061 | **~8.2× 更快** |

> 说明：标量基线为 C 循环实现（非最优 RVV vwmacc 组合）；vdot 单指令完成 4×4 点积+累加。emu 为 -O0 构建，但周期为 RTL 真实周期。

**注意力 kernel 实测（2026-08-18，S=4, d=16，QKᵀ vdot + softmax + PV vdot）**：emu 差分通过（GOOD TRAP），**2,665 指令 / 10,088 周期**，softmax 输出与标量参考一致。注：softmax 当前用标量实现（kunminghu-v2 RTL 的 RVV 浮点 lane≥1=0 局限，见 08 §3.3）。

### 5.3 实验对照原则

- 同一套 kernel 框架、同一量化参数、同一分块参数下，仅替换"点积原语"（vdota4 vs RVV 组合），保证对比公平。
- 数据可复现：固定 seed、固定镜像、记录环境（commit SHA、编译选项、仿真器版本）。

## 6. 面积 / 功耗 / 时序评估方法

| 项目 | 方法 | 输出 |
| --- | --- | --- |
| 面积 | vdot 执行单元单独综合（如 Synopsys DC，28nm/12nm 工艺库；或开源的 OpenROAD/Yosys 流程），与全核面积（昆明湖公开数据/估算）对比 | 新增面积占比（目标 ≤ 0.5%） |
| 功耗 | 综合后功耗报告（switching activity 用基准波形回标），对比 vwmacc 组合路径 | TOPS/W 对比 |
| 时序 | 关键路径分析：8×8 乘法 + 加法树 + 累加器 vs 目标频率（昆明湖主频假设） | 是否满足目标频率，若不满足给流水切分方案 |

**口径说明**：
- "面积占比 ≤ 0.5%"：以 vdot 单元（含解码/调度附加逻辑）综合面积 ÷ 全核估计面积（以昆明湖公开的面积/器件数数据为基准，无法获取时给出估算值与假设）。
- 若独立单元面积不达标或时序吃紧，启用备选实现（复用 VectorMul 数据通路，见 [03 微架构设计](./03_微架构设计.md) §7）。

## 7. 回归策略与 CI

- **每日回归**：L0 指令级 + L1 difftest 冒烟（固定 seed 集）。
- **提交前门禁**：L0–L2 全量 + B1 基准（防性能回退，记录 commit → 指标曲线）。
- **工具**：复用香山现有 CI 模式（GitHub Actions 跑 emu 冒烟）扩展 vdot 测试 job；本地用 `tools/verification-driver` 的模板生成场景用例。
