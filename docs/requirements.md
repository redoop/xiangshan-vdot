# 01 需求分析与方案总览

> 赛题：面向边缘 AI 大语言模型推理的 RISC-V 自定义 vdot 指令设计——基于"香山"昆明湖 V2 处理器架构
> 本文档回答三个问题：**为什么做**（背景与缺口）、**做什么**（目标与指标）、**怎么做**（总体技术路线与创新点）。

---

## 1. 背景：点积是 LLM 推理的性能与能效瓶颈

点积（Dot Product）是深度学习最核心的计算内核：

- **Transformer 架构的 LLM** 中，自注意力机制的 QKᵀ 与 AV 矩阵乘、FFN 的两次 GEMM，全部由海量点积构成。以 GPT-2 为例，点积占**总计算量 70% 以上**。
- **推荐系统**中，78% 的个性化推荐以点积作为核心排序指标（用户向量 × 商品向量的匹配度计算）。
- 在**边缘端**部署 LLM 时，点积的执行效率直接决定推理延迟、吞吐与能效，是资源受限场景下"能不能跑、跑多快"的关键。

### 1.1 为什么是 INT8 量化

边缘 LLM 推理的主流实践是 **INT8 量化**（W8A8）：

| 因素 | 说明 |
| --- | --- |
| 能效 | INT8 乘法器面积/功耗约为 FP32 的 1/10~1/20，INT8 算力密度（TOPS/mm²）远高于 FP16/FP32 |
| 精度 | 感知量化（PTQ：per-tensor / per-channel / per-group）在 7B 以下模型上可保持接近 FP16 的困惑度/任务精度 |
| 生态 | llama.cpp / ggml、vLLM、TensorRT-LLM 等主流推理栈均有成熟的 INT8 量化与 GEMM kernel |

因此，**一条高效的 INT8 点积指令**是边缘 LLM 推理的核心加速原语。

## 2. 缺口：RVV 1.0 没有原生整数点积指令

昆明湖 V2（Kunminghu V2）完整实现 RISC-V 向量扩展 **RVV 1.0**（VLEN=128，SEW=8/16/32/64，支持掩码、尾元素、分段访存等）。但 RVV 1.0 的指令集中**没有一条"一组 INT8 元素点积累加"的原生指令**：

- 现有做法是组合 `vwmaccu.vv`（INT8×INT8 → INT16 宽乘累加）完成 INT8→INT16 累加，再**加宽**到 INT32，或改用 `vwmacc` 链。完成一次 INT32 累加需要**多条指令**：拆包/符号扩展（`vzext`/`vsext`）、`vwmaccu`、累加位宽扩展（`vwmacc` → INT32 需逐级加宽）、必要时再 `vnsrl` 打包回 INT8 布局。
- 后果：**指令数多、寄存器压力大、动态功耗高、吞吐低**——INT8 GEMM 的 K 维累加被"拆包 + 加宽 + 打包"的胶水指令拖累，无法发挥 128-bit 数据通路的峰值乘加能力。

### 2.1 行业对照：生态正在向"原生 vdot"收敛

| 来源 | 指令/扩展 | 形态 |
| --- | --- | --- |
| RISC-V 官方（fast-track，Ratification Plan 进行中） | **Zvdot4a8i / Zvqdotq** | 4×INT8 点积 → INT32 累加（`vdota4.vv` 等），RVV 编码空间，LLVM 已有支持 PR |
| SiFive | Xsfvdot / Xsfvqmaccdod / Xsfvqmaccqoq | 自定义 INT8 矩阵乘-点积扩展，QEMU/LLVM 已有实现 |
| SpacemiT | XSMTVDot | 自定义向量点积扩展，已合入 LLVM |
| 香山昆明湖 | 无 | **缺口**——这正是本赛题的切入点 |

> 结论：为昆明湖 V2 设计并实现一条**自定义 vdot 指令**，既是解决边缘 LLM 推理实际痛点的工程问题，也与 RISC-V 官方正在推进的 Zvdot4a8i 方向一致，具备前瞻性与兼容路径。

## 3. 目标与范围

### 3.1 目标

在香山昆明湖 V2 处理器上：

1. **设计一条（族）自定义 vdot 指令**：4×INT8×INT8 → INT32 累加，遵循 RVV 1.0 的 vl/vstart/掩码/尾元素语义，编码尽量与官方 Zvdot4a8i 对齐。
2. **在昆明湖 V2 向量后端完成硬件集成**：解码接入 + 专用执行单元（或扩展现有向量乘法数据通路），以极小面积开销换取数倍点积吞吐提升。
3. **打通软件栈**：NEMU/Spike golden model、LLVM/binutils 汇编支持（或 intrinsic 头文件）、INT8 量化与 GEMM/注意力 kernel、端侧小模型推理演示。
4. **完成验证与评估**：指令级测试 + difftest 协同仿真 + 基准对比（指令数、周期、吞吐、能效），给出可量化的收益证据。

### 3.2 目标工作负载

| 负载 | 计算形态 | vdot 的作用 |
| --- | --- | --- |
| LLM 自注意力 QKᵀ / AV | INT8 GEMM（M=1~32 的 GEMV/GEMM） | 每 4 元素一点积，一条指令完成 4 组累加 |
| FFN 两层 GEMM | INT8 GEMM，K 大（如 4096） | K 维内循环全部由 vdot 承担 |
| Embedding / 输出层 | INT8 GEMM / 点积打分 | 同上 |
| 推荐系统双塔 | 向量点积打分 | 单指令即一次 4 元素点积 |

### 3.3 指标（验收口径）

| 类别 | 指标 | 目标值（相对 RVV 1.0 vwmacc 基线） |
| --- | --- | --- |
| 指令效率 | INT8 GEMM 每输出元素所需指令数 | 下降 ≥ 50% |
| 吞吐 | vdot 单元吞吐 | 1 条/周期（VLEN=128，每周期 ≥ 4 组 INT32 累加） |
| 面积 | 新增硬件面积（含解码/调度） | ≤ 全核面积 0.5%（估算口径见微架构文档） |
| 能效 | INT8 GEMM TOPS/W | 提升 ≥ 2×（以估算/仿真口径） |
| 正确性 | difftest 回归 | 全量通过，0 失配 |
| 演示 | 端侧小模型（≤2B）INT8 推理 | 可运行，per-token 延迟数据可复现 |

> 注：以上目标值为设计指标，最终以评估结果为准并如实报告；量化口径（周期 vs 门数）在对应文档中定义，避免口径不一致。

## 4. 总体技术路线

```
┌─────────────────────────────────────────────────────────────────┐
│  阶段一：环境部署与验证（基线）                                    │
│  xs-env + XiangShan(kunminghu-v2) + NEMU + emu/difftest 跑通     │
│  riscv-tests / coremark 基线数据采集                              │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│  阶段二：vdot 设计与实现                                          │
│  ISA 规格 → NEMU/Spike golden → RTL（解码+执行单元） →            │
│  LLVM/binutils/intrinsic → 单元测试                               │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│  阶段三：协同仿真与评估                                           │
│  difftest 回归 → 基准（micro/GEMM/端到端）→ 面积功耗时序评估 →     │
│  文档与提交                                                      │
└─────────────────────────────────────────────────────────────────┘
```

关键决策点（详见各分文档）：

1. **指令形态**：采用 RVV 1.0 编码空间的 4×INT8→INT32 点积（对齐 Zvdot4a8i 语义），而非自定义主操作码——保证继承 vl/vstart/掩码/尾元素语义，difftest 与工具链改动最小（见 02）。
2. **硬件实现**：优先**独立小执行单元**挂入向量 ExeBlock，复用 VPRF 读端口与 writeback 端口；备选方案为扩展现有 VectorMul 数据通路（见 03）。
3. **软件推进顺序**：golden model（NEMU）先行 → 内联汇编/intrinsic 先行验证算法 → LLVM 完整支持后置（见 04）。
4. **验证策略**：golden-model 差分随机测试为主，difftest 全量回归兜底（见 05）。

## 5. 创新点

1. **指令级创新**：面向 INT8 量化 LLM 推理的 4×INT8→INT32 原生点积指令，语义完整对齐 RVV 1.0（vl/vstart/掩码/尾元素/异常），编码与 RISC-V 官方 fast-track 提案 Zvdot4a8i 保持一致，具备直接演进为官方扩展的路径。
2. **微架构创新**：在昆明湖 V2 向量后端中以"极小面积开销换取数倍点积吞吐"为设计目标，给出乘加阵列 + 加法树 + 累加器的数据通路设计、时延/吞吐权衡与面积功耗估算方法。
3. **系统级创新**：打通"ISA → 硬件 → golden model → 编译器 → 量化 → GEMM kernel → LLM 推理"全链路，交付可复现的端到端演示与评估数据，而非仅有 RTL 代码。
4. **工程创新**：利用香山敏捷开发基础设施（difftest、随机差分测试、emu 周期仿真）建立"指令语义 → 硬件 → 参考模型"三方一致的可验证闭环。
