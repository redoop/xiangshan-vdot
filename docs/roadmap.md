## 3. 依赖与关键路径

```
1.4 编码核对 ─► 2.1 ISA 定稿 ─► 2.2 golden ─► 2.6 指令级测试
              └► 2.3 解码 ─► 2.4/2.5 RTL ─► 3.1 difftest ─► 3.2/3.4 评估
1.2 环境基线（全程依赖）        2.7 kernel ─► 3.3 演示
```

- **关键路径**：1.2 → 1.4 → 2.3 → 2.5 → 3.1 → 3.2。
- **可并行支线**：golden model/软件仿真/kernel（2.2/2.6/2.7）与 RTL（2.3–2.5）互不阻塞；LLVM（2.8）可全程并行。
- **风险缓冲**：阶段二预留 1 周缓冲。

## 4. 风险与备选方案

| 风险 | 影响 | 概率 | 缓解/备选 |
| --- | --- | --- | --- |
| 官方 Zvdot4a8i 编码冻结且与候选冲突 | 编码返工 | 中 | 以官方为准切换编码（改动集中在解码表+工具链，执行单元不变）；文档公开冲突矩阵 |
| 执行单元时序不满足目标频率（乘加链过长） | 性能不达标 | 中 | 流水切分（乘/加树/累加各一拍，时延 2–3 周期）；或扩展 yunsuan `VIMac64b` 增加点积模式复用其 2 级寄存器结构（备选实现，见 03 §7） |
| difftest 失配（NEMU 语义 bug / RTL 边界 bug） | 验证阻塞 | 中 | 三方随机差分先行定位（05 §3）；失配自动最小化复现 |
| LLVM 支持工作量超预期 | 编译支持延期 | 中 | 保留内联汇编 intrinsic（04 §3.3）作为主路径，LLVM 降级为加分项 |
| 打包/量化格式与 vdot 布局不匹配导致性能损耗 | 收益打折 | 中 | 权重离线打包；激活打包成本在 B1 中单独报告；kernel 分块参数调优 |
| emu 仿真速度慢（端到端演示） | 演示耗时 | 低 | 用小模型 + 短 prompt；或 NEMU 纯软件演示 + emu 抽样验证 |
| 昆明湖 V2 源码获取/编译环境问题 | 全盘阻塞 | 低 | xs-env 官方流程 + 大赛答疑通道；备选 master 分支（注明差异） |
